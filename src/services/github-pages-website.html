A website on GitHub Pages, built with the SEO already done

Most new websites launch and then wait for someone to do the search work. I build small business sites on GitHub Pages with that work finished on the first day: every page crawlable as plain HTML, titles and descriptions written for the searches that matter, structured data that names the business, and the site registered with Google and Bing before anyone announces it. The domain sits in your Cloudflare account and the code in your GitHub repository, so the finished site belongs to you outright.

What an SEO adds to the build

Plenty of people can put pages on GitHub Pages. The difference here is what happens between the design and the launch. Before a site goes live, I check it the way a crawler will meet it:

  • Indexing. Every page answers 200, carries its own canonical URL, and sits in an XML sitemap that lists only pages meant for search.
  • Titles and headings. One clear H1 per page, unique titles near sixty characters, and descriptions that read like an answer to the search.
  • Structured data. JSON-LD for the business, its services, and its people, matching what the visible page says.
  • Search Console and Bing Webmaster Tools. Both verified in your name, the sitemap submitted, and the first pages requested for indexing.
  • AI crawlers. A robots.txt that welcomes the search and answer engines by name, and an llms.txt that tells them where the important pages are.
  • Accessibility and speed. Alt text, real links, readable contrast, and pages light enough that Core Web Vitals take care of themselves.
